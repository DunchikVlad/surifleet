## Наблюдения (не баги)

- `TestKeyPairPersistedAcrossRestarts` (internal/samlauth) падает на
  Windows-стационаре: тест ожидает права 0600 на sp.key.pem, а Go на
  Windows не применяет Unix-биты прав (stat отдаёт -rw-rw-rw-). Проблема
  платформы запуска тестов, не кода: на linux-стенде (.28/.67) права
  выставляются корректно. Проверено при деплое чанков 105–108
  (2026-10-11): единственный FAIL прогона, остальные пакеты ok.
- `systemctl reload suricata` на .67 занимает ~60 с (53k правил, live
  rule swap) — синхронные service_action/деплои надо ждать с запасом
  (сервер ждёт 150 с, см. SendTaskAndWait). Плюс замечен зависший с
  18:59 reload-джоб (3 ч, unix-manager: broken pipe в suricata.log) —
  новый reload его «выталкивает», юнит возвращается в active; если
  reload висит — проверить `systemctl list-jobs` на сенсоре.
- `GET /hosts/{id}/discovery` возвращает 404 «discovery ещё не прислан
  агентом» для хоста `sensor-01-dc1` (`0cd2971e-…`) — хост создан вручную,
  агента за ним нет; поведение корректное. На хосте `test1` (реальный
  сенсор) discovery отдаёт 200.
- `audit_log/verify`: `checked` > `chained` (184 vs 135 на 2026-10-10) —
  записи, писавшиеся до включения `server.audit_hash_chain`, хэша не имеют
  и корректно пропускаются.

## Закрытые

### KI-1. Цепочка хэшей аудита: запись не проходит пересчёт hash — ЗАКРЫТО (чанк 107)

- **Закрыто**: 2026-10-11, чанк 107 (коммит см. git log).
- **Симптом (было)**: `GET /audit_log/verify?limit=200` → `ok:false`,
  `broken_at: 4e34bdef-…`, «hash записи не совпадает с содержимым».
- **Корень**: при записи хэш считался от исходной сериализации diff
  (`json.Marshal`: bytewise-порядок ключей, HTML-эскейп `\u003c`), а
  jsonb в PG нормализует документ (ключи по (длине, байтам), компактная
  форма, без HTML-эскейпа) — verify читал нормализованный текст и хэш
  не сходился.
- **Фикс**: `logChained` канонизирует diff round-trip'ом
  `SELECT $1::jsonb::text` в той же транзакции ДО вычисления хэша —
  каноническая форма по построению совпадает с тем, что прочитает verify
  (`internal/store/audit_chain.go`, `canonicalizeDiff`). Юнит-тесты:
  `TestCanonicalizeDiffRoundTrip` (формула KI-1-примера, хэш записи ==
  пересчёт verify; NULL → nil), `TestCanonicalizeDiffError`.
- **Хвост — историческая битая запись — УСТРАНЕН 2026-10-11** (при перекате
  чанков 105–108 на .28): цепочка пересчитана ВПЕРЁД одноразовой Go-утилитой
  (тот же алгоритм `canonStr`; перед мутацией — self-check на пост-фикс
  записях: 9/9 пересчитались совпадая с хранимым hash; бэкап —
  таблица `audit_log_backup_20261011`, удалить после недели спокойной
  работы). Переписано 159 записей (hash/prev_hash), битых было 2
  (`4e34bdef-…`, `89f21cbe-…`, обе rules.update от 2026-10-07 с diff).
  Запись о ремонте — `audit.chain_repair` (`f0aa35dd-…`). Итог:
  `GET /audit_log/verify?limit=1000` → `ok:true`, checked 200 / chained 160.
  Первоначальный план (для истории): временно снять триггер
  `audit_log_no_update_delete` (функция `forbid_append_only_mutation`),
  пересчитать цепочку вперёд от первой битой записи (каждая: diff →
  `diff::jsonb::text`, hash = SHA-256 канон-строки по алгоритму `canonStr`,
  prev_hash = hash предыдущей пересчитанной), вернуть триггер; запись о
  ремонте — в аудит. Всё выполнено в одной транзакции.

### KI-2. Telegram: нет уведомления «агент снова онлайн» — ЗАКРЫТО (чанк 103)

- **Закрыто**: 2026-10-10, чанк 103 (коммит см. git log).
- **Фикс**: хаб публикует online при реальном переходе (`SetStatus`
  возвращает факт смены; Hello — новая точка `emitStatus`, раньше
  online уходил только из heartbeat-revive); recovery-сообщение уходит
  через `notify.OfflineTracker` — только если offline-эпизод зафиксирован
  этим процессом (защита от reconnect-шторма/флапов, повторы глушит
  дедуп 10 мин); текст содержит длительность недоступности.
- **Живая проверка (при перекате .28)**: остановить агента .67 →
  offline-уведомление → запустить → «агент снова онлайн (был
  недоступен N)».

### KI-3. Telegram: в сообщениях нет IP и hostname агента — ЗАКРЫТО (чанк 103)

- **Закрыто**: 2026-10-10, чанк 103.
- **Фикс**: `hub.OnAgentStatus` передаёт IP (захваченный из реестра до
  удаления при offline); эмиттеры (`cmd/server/notify.go`) пишут
  единый формат «Агент <hostname> (<IP>), кластер <name>, …» для
  offline/online и «хост <hostname> (<IP>)» в уведомлениях о провалах
  деплоев; fallback — `ip_addresses` карточки хоста.
- **Живая проверка (при перекате .28)**: любое агент-событие → в
  Telegram видны hostname и IP.

### KI-4. Telegram: нет уведомления о неудачном обновлении правил — ЗАКРЫТО (чанк 103)

- **Закрыто**: 2026-10-10, чанк 103.
- **Фикс**: `Orchestrator.OnTaskFailed` (провал из `failTask` и из
  `HandleTaskResult`) → событие `deploy.task_failed` с контекстом:

  сохранена). Дедупликация по задаче (окно 10 мин).
- **Живая проверка (при перекате .28)**: задеплоить заведомо битый
  ruleset → задача failed → в Telegram уведомление с причиной.
