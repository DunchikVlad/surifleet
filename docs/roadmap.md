## Приоритет 1 (наивысший — ближайшие чанки)

### 1A. Правила и ruleset'ы (5.1 + новые требования)

- **Просмотр состава ruleset'а**: какие правила внутри версии (список
  sid/msg из UI, drill-down из вкладки «Ruleset'ы»).
- **Версия ruleset'а прорастает наряду с хэшем**: сейчас «version» —
  по сути имя/строка; нужна нормальная версия (semver/автоинкремент),
  видимая в списке ruleset'ов, деплоях, на странице инстанса
  (desired/actual: версия + хэш).
- **Редактирование правил и создание своих на их основе**: форма
  редактирования (msg/контент опций), «клонировать» → новое правило с
  новым sid (из локального диапазона 9000xxx) и именем.
- **Контроль дублей sid**: при сборке ruleset — отказ/предупреждение
  при повторных sid; в репозитории sid уникален по (org, sid) уже есть —
  проверка нужна на состав ruleset'а и при импорте из разных источников
  (предупреждение «sid уже есть от другого источника»).
- **Экспорт правил**: `GET /rules/export?format=text|stix|dataset`
  (text = .rules по фильтру; stix — bundle; dataset — Suricata Dataset).
- **Таргетинг на уровне ruleset**: ruleset может быть собран под
  подмножество кластеров/хостов (не только деплой-таргетинг).
- **Сортировка в вебе по дате и другим полям** (правила, деплои,
  ruleset'ы, аудит — кликабельные заголовки колонок).
- Оценка: 3–4 чанка.

### 1B. Конфигурации (5.3 — редактор suricata.yaml)

- **Редактирование /etc/suricata/suricata.yaml на управляемых агентах**
  из UI: чтение текущего конфига с сенсора (агент читает файл по
  запросу), редактор в вебе, версии конфигураций (история).
- **Деплой-конвейер конфигов**: бэкап → запись → валидация
  `suricata -T` на агенте → reload/restart → откат при провале
  (переиспользует волновой деплой и watchdog; новый тип задачи
  deploy_config).
- **Профили конфигураций** (шаблоны по кластеру с переменными).
- **Откат конфигурации** (append-only история, rollback = новый деплой
  прошлой версии).
- Открытый вопрос ниже: весь файл vs managed-секции.
- Оценка: 3–4 чанка.

### 1E. Правила — редактор, скачивание ruleset'ов, матрица (согласовано 09.10)

Ставится сразу после начатого 1B (рендер профилей + волновой деплой),
выше прочего:

- **Редактор правил с логикой и проверкой** (вкладка «Правила» вместо
  prompt'а «ред.»): структурный разбор internal/rules (action/proto/
  src/dst/опции), raw-режим, отображение логики детекта (буферы,
  content/pcre, classtype/priority); кнопка «Проверить» — валидация
  парсером server-side и через агента (кандидат во временный ruleset →
  `suricata -T`; флаг validate_only в DeployRulesTask или отдельная
  задача — решить на месте).
- **Скачивание ruleset'ов** (вкладка «Ruleset'ы»): кнопка «Скачать» у
  версии → GET /rulesets/{id}/download (.rules рендер internal/ruleset,
  attachment + ETag по образцу POST /rules/export).
- **Матрица «правила × инстансы»**: раскрытие строки → та же карточка
  логики правила + raw + статус ячеек (компонент общий с «Правилами»).
